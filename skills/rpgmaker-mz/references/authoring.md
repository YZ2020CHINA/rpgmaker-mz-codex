# MZ 内容制作要点

本指南提炼自 Redseb/rpgmaker-mz-mcp authoring skill，并针对中文 MZ 工作流改写。原项目 MIT 许可证保存在插件 UPSTREAM-LICENSE.txt。

## 地图

MZ 地图 data 有 6 层，索引 `(z * height + y) * width + x`。0–3 为图块层，4 为阴影，5 为区域。第 0 层先铺不透明草地/地板；道路、森林等透明自动图块放第 1 层；建筑等 B–E 装饰通常放第 2 层。直接把半透明自动图块铺到空白第 0 层会露黑底。

先核对地图 tilesetId，再用相同图块集的 `find_tile` 查语义 ID，不猜 ID。自定义贴图的外观和目录需实际查看；默认图块目录不代表自定义素材。`resize_map` 才负责尺寸变化，`update_map` 不用于替换图块数组。空白地图没有可通行地面，必须先铺地并检查出生点。

## 事件

MZ 事件触发：0 确认键、1 玩家接触、2 事件接触、3 自动执行、4 并行。与人物相同优先级为 priorityType 1；低于人物为 0。玩家朝向门/招牌按确认键的事件一般设相同优先级。可走地垫传送可用低于人物和玩家接触。避免不可达事件、无图像的实体墙，以及不结束的自动执行事件。

一次性宝箱/战斗使用两页：第一页执行并开启独立开关 A；第二页以该独立开关为条件显示完成状态。事件页由后向前选满足条件的最高页，条件和优先级必须实际测试。移动路线设置可跳过受阻步骤，防止卡死剧情。

MZ 显示文字没有自动换行，每个消息框通常最多 4 行。中文全角字比英文宽，不能套用英文字符数上限；按字体、头像占位与窗口宽度断行，并通过试玩截图检查。默认字体缺少中文字形时需要合法可分发的中文字体或合理 fallback；不要把系统商业字体直接塞进插件包。

## 战斗

自定义职业/角色注意命中率 trait 和技能类型 trait；只有学习技能却没有可用技能类型会导致战斗菜单不可用。用 `list_assets` 验证敌人立绘、侧视战斗图和音效名称。战斗属性、状态、技能伤害不仅要通过结构校验，还应实际跑一次战斗。

## 试玩证据

`validate_*` 只能证明结构与引用。`render_map` 检查画面；`run_playtest` 检查真正的流程。地图、入口、NPC、一次性开关与战斗分别选能证明行为的步骤。比较预期与返回状态，检查 problems、消息文本和截图；调用成功不等于测试通过。
